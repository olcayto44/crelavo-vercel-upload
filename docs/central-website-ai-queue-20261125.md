# Durable isolated Website AI queue
Separate enqueue transaction reserves credits once, worker claim moves queued to claimed exactly once, stale claimed jobs move to reconciliation with no retry or refund. The existing internal runner consumes an already-enqueued job; it does not create or poll jobs. No daemon, external queue service, live DB migration or live payment activation. Studio Brief & Plan has a read-only authenticated status refresh (no mutation). Status projection includes durable queue and provider-cost milestones and refuses mismatched job/owner/plan. Existing local generation remains synchronous. Embedded DB tests now cover queued reservation, idempotent enqueue, claim, stale hold, no replay, artifact and settlement. Real worker process, budget/rate policy, independently verified provider cost, concurrent SQL tests and signed-in browser acceptance still required.
